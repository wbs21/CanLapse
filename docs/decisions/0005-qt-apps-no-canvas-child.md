# 0005 · Qt 系绘画软件没有"画布子窗口"

状态：**已实测确认**（2026-10-17，Krita 5.x，Windows 10）

## 实测结论

Krita 的顶层窗口**没有任何后代窗口**：

```
顶层窗口 0x1A0C3C  进程=krita.exe  类名=Qt5157QWindowToolSaveBits  标题="多功能拾色器 - Krita"
（以上为该顶层窗口的全部后代窗口）        ← 0 个后代
```

原因是 Qt 的 **alien widgets**：Qt 自己把整个界面（画布、面板、工具栏）绘制到
一个顶层 HWND 里，内部控件**不占用 Win32 子窗口**。因此：

* `EnumChildWindows` 拿不到画布；
* `WindowFromPoint` 落在画布上时返回的也是**顶层窗口本身**；
* 本工具赖以工作的"顶层缩略图 + rcSource 裁剪子窗口矩形"这条路，
  在 Qt 系软件上**退化为"只能录整个窗口"**。

对照：SAI2（自绘 Win32 窗口）有真实的画布子窗口
（`sflChildWindow` 651×761），所以能只录画布 —— 这也是本工具最初的设计目标。

## 影响范围

| 软件 | 界面框架 | 有无画布子窗口 | 本工具表现 |
|---|---|---|---|
| SAI2 | 自绘 Win32 | ✅ 有 | **只录画布**（最佳）|
| Photoshop | 自绘 | ✅ 有（多数版本）| 预期同 SAI2，待真机验证 |
| Clip Studio Paint | Qt | ❌ 无 | 只能录整个窗口 |
| Krita | Qt | ❌ 无 | 只能录整个窗口 |

## 因此给用户的建议

对 Qt 系软件，让"整个窗口"等于"画布"即可 —— 各家的"全屏画布 / 画布专注"模式正好做这件事：

* **Krita**：按 `Tab` 进入 **Canvas-only mode**（隐藏所有面板，只剩画布）；
* **CSP**：`视图 → 全屏` 或隐藏调色板；
* 此时用本工具录**顶层窗口**，效果与"只录画布"基本一致。

这比让用户手工框选区域更省事，也不需要在产品里引入"手动裁剪矩形"这种新概念。

## 附带发现：`--title` 匹配要小心

`dwm_capture_spike --tree "Krita"` 匹配到的是**第一个**标题含 "Krita" 的顶层窗口，
而它是「多功能拾色器 - Krita」这个弹窗，**不是主窗口**（主窗口标题是
`03.kra (18.4 MiB) * - Krita`）。

* 现在：命令行请优先用 `--hwnd`；图形界面用鼠标拾取不受影响。
* 待办：`--title` 匹配应优先选择**面积最大的**候选，或在多命中时列出让用户选。
