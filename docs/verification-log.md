## 一、捕获（DWM 窗口缩略图）

| 项 | 结论 | 证据 |
|---|---|---|
| 取到像素 | ✅ | 宿主窗口 `PrintWindow(PW_RENDERFULLCONTENT)` 读回缩略图；`BitBlt` 宿主 DC 只会拿到宿主自身涂色（品红均值 170.0）|
| 子窗口 | ✅ | `DwmRegisterThumbnail` 对子窗口返回 `0x80070057`；改为注册**顶层根**+`rcSource`=子窗口矩形，DWM 1:1 裁剪。SAI2 画布子窗口 `sflChildWindow` 651×761 / 客户区 625×715 |
| 跟随缩放/移动 | ✅ | 单测「子窗口裁剪矩形随子窗口移动与缩放」（自建父子窗口，不动用户软件）|
| 被遮挡 / 最小化 | ✅ | 可见 / 被遮挡 / 最小化三种状态均取到正确像素（spike 实验）|
| 不串入其他软件 | ✅ | 架构保证：只渲染源窗口及其 **owned** 窗口；别的进程窗口不属于该属主组 |
| 软件自家浮动面板 | ✅（已知行为）| DWM 会把 owned 窗口一起渲染，所以 SAI2 的「颜色」面板会出现在画面里（实测遮挡 20.4%）。**按用户要求：不提示、不裁切** |
| 大窗口（大于屏幕）| ❌ | spike 验过 3840×2160 能出像素（角标证明整帧 1:1），但**产品路径**未验；本次尝试做 4K 压测时，测试窗口被 Windows 约束到客户区 3604×1061，未能覆盖此档 |

## 五、打包

| 项 | 结论 | 证据 |
|---|---|---|
| 两个入口 | ✅ | `CanLapse.exe`（GUI，windows 子系统，**无 ConsoleWindowClass**）/ `canlapse-cli.exe`（CLI，`doctor` 全绿，无参数打印帮助）|

| 图标：第 ④ 条的线索 | ⚠️ | 走"构建后注入"绕开 link.exe 的**资源输入**：`rc → .res → link /dll /noentry → res.dll → LoadLibraryEx(LOAD_LIBRARY_AS_DATAFILE) + 枚举 + UpdateResourceW`。注入本身报成功（`types=1 copied=1 end=True`），但 exe 的版本信息仍空、图标仍默认。**关键线索：中间 res.dll 里只枚举出 1 种资源类型**（`.rc` 里实为 3 种：ICON / GROUP_ICON / VERSIONINFO）—— 即 `link.exe` 同样没能完整吸收这份 `.res`。对照：`lib.exe` 能正常吸收（产出 1994 字节 `.lib`）。**因此根因不在注入代码，而在 link.exe 与这份 .res 的兼容性**；下次应优先查"rc.exe 版本 → link.exe 版本"的组合（本机 rc 10.0.28000 / link MSVC 14.52 insiders），例如改用与 link.exe 同版本的 rc.exe（MSVC 自带的 rc）|

## 七、还缺的唯一实质验证

**一次完整绘画过程的缩时**（连续作画 1~3 分钟 → 几十帧 → 观感连贯的成片）。

尝试过 5 次、4 种内容源（SAI2 画布 / Krita 画布 / 对话窗口 / 后台窗口），
在真实绘画软件上最多只得到了 2 帧 —— 因为**那些内容在录制期间确实没有变化**，
差分逻辑正确地把重复帧丢弃了。**这一项只能由真人作画触发。**

对 Qt 类软件（Krita/CSP）还有一条使用建议：按 `Tab` 进 Canvas-only mode，
让"整个窗口"就等于"画布"（理由见 ADR 0005）。

## 八、运行中才发现的缺陷（提醒：不要只靠读代码验收）

1. 悬浮条的时长/帧计数写在**无标题栏窗口的标题**里 → 用户根本看不见
2. exe 是控制台子系统 → 双击弹黑框
3. `CanLapse.exe` 与 `canlapse.exe` **大小写同名互相覆盖** → GUI 入口从未生效
4. 重新导出的产物落在会话目录内 + 自动清理 → **刚导出的视频被自己删掉**
5. 大图预览弹窗创建在绘画软件**后面** → 用户以为"打不开"
6. 命令行录后台窗口时新规则导致**一直暂停、一帧不出** → 补 `--no-fg-pause`

## 附：版本信息（RT_VERSION）读不出来的真正原因

**结论（实测，决定性）**：注入后 exe 里的 `RT_VERSION` 是**空壳** ——
枚举 exe 自身资源得到：

```
RT_ICON       : 名字数=7  语言=0409×7        首个大小=645 字节
RT_GROUP_ICON : 名字数=1  语言=0409          首个大小=104 字节
RT_VERSION    : 名字数=1  语言=(空)          首个大小=0 字节     ← 空壳
RT_MANIFEST   : 名字数=1  语言=0409          首个大小=1661 字节
```

即：该类型下有一个**名字项**，但**没有语言子项、数据为 0 字节**。
因此 `.NET FileVersionInfo`（以及资源管理器"详细信息"）读出全空 —— 与读取方无关。

已排除的假设：**语言块**。`080404b0`+`0x804` 与标准 `040904b0`+`0x409` 实测结果相同。

下一步方向（给未来的自己）：问题出在 `tools/ResInject.cs` 的复制逻辑 ——
对 `RT_VERSION` 这类资源，源端的语言枚举可能返回 0/空，导致
`UpdateResourceW(..., lang, data, size)` 以 `lang=0 且 size=0` 写入，只留下名字项。
修法建议：
1. 复制前**先校验源资源的大小**（`SizeofResource` 为 0 就报错，别再默默写入）；
2. 语言为 0/空时**回退到 0x409**；
3. 写完后**回读校验**目标 exe 的资源（本次这个枚举函数即可直接复用）。

教训同上：这次也是"没有报错却什么都没做成"（复制计数 `copied=9` 里包含了这个空壳）。

## 附：CSP 真机验证 + 真实绘画过程缩时（已完成）

### 1) CSP 5.0.4 可捕获，且有画布子窗口

- 进程 `clipstudiopaint504.exe`；每个文档是一个顶层窗口
- 文档顶层窗口 1061×874 的画面含**文档标签栏**；其子窗口 1051×826（相对客户区 `(5,43)`）
  即画布视图区域，不含标签栏
- 类名是 GUID 形式，无法按类名识别 → 依赖鼠标拾取
- 详见 ADR 0005 的"实测更正"一节

### 2) 真实绘画过程的缩时：**首次成功**

目标：CSP 画布子窗口 `0x380BC6`（1051×826），被动录制 90 秒（2fps，阈值 0.002）：

```
录制结束：36 帧，0 个标记，丢弃 0，耗时 01:30
合成：36 帧 -> 1050x826，418,620 字节
ffprobe：h264 / High / 1050x826 / nb_read_frames=36 / duration 3.000000 秒
交叉核对：36 ÷ 12fps = 3.000 秒  ✔ 精确吻合
```

帧序可见真实笔触推进（红色加粗 → 清空 → 蓝色粗笔触 → 成形 → 红线叠加），
证据：`csp_timelapse.mp4`、`csp_session_montage.png`。

**这一项此前是唯一未达成的实质验证**（在真实绘画软件上最多只得到 2 帧），现已关闭。
