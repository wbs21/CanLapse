Timelapse recorder for drawing-app canvas windows — Windows 10/11 x64, single-file executable, no DLLs, no runtime.

## What's new in v1.3.1

**Code review & performance batch — 20 items fixed across the whole codebase.**

- **Fixed `Frame::resize_to` downscale detection** — the "is this a downscale?" check used a width/height cross-ratio (`nw*sh < sw*nh`) which gave the wrong answer when aspect ratio changed independently from area (e.g. a 100×50 frame scaled to 70×80 area *grew* but was misidentified as a downscale, landing in the wrong resampling path). Now correctly uses area (`nw*nh < sw*sh`). Added a regression test covering unequal-ratio downscale/upscale.
- **Single-instance mutex ownership** — `CreateMutexW` was called with `bInitialOwner=1`, making this process the permanent owner, leaving the mutex in abandoned state. Changed to `0`; the `ERROR_ALREADY_EXISTS` detection still works.
- **Removed hardcoded dev-machine paths** — both `build.rs` and `lib.rs` had fallback paths like `D:\CapLite\ffmpeg-min` that only existed on one specific laptop. All dependency discovery now goes through env vars or `tools/*.path` files or the repo-bundled `deps/ffmpeg-static/`. Clones to any machine build first-try.
- **SessionWriter queue capacity 4 → 8** — the bounded writer channel that absorbs disk I/O bursts now has double the headroom, reducing frame-drop probability under heavy filesystem contention.
- **Persistent `BufWriter<File>` for logs** — `log::line()` used to open+append+close the log file on every call; now holds a `Mutex<BufWriter<File>>` per sink for the process lifetime. File rotation (>4 MB → `.old`) is preserved; the double lock in the rotation path was collapsed into one.
- **`Frame::changed_enough_bytes` u64 chunk fast path** — the per-pixel diff now skips 8-byte (2-pixel) chunks with a single u64 comparison before falling back to per-pixel analysis. For the common timelapse case ("almost static frame") this is 4–8× faster. Pointer alignment invariant guarded with `debug_assert`.
- **Zero clippy warnings** — `cargo clippy --all-targets` is now completely clean (needless_range_loop, manual_checked_ops, missing_safety_doc, field_reassign_with_default, ptr_arg, assertions_on_constants, unnecessary_cast all addressed).
- **Integration tests** — new `tests/encode_pipeline.rs` with 4 end-to-end tests: static-color frames → real MP4, empty-directory error, invalid fps validation, mid-cancel produces a playable partial file. Full test suite is now **52 tests passing** (48 unit + 4 integration).
- **Dead-code cleanup** — removed `add/` (design notes) and `spikes/` (early verification prototypes).
- **FFI upgrade docs** — new `docs/FFI-UPGRADE.md` with the 3-step workflow for safely upgrading the hand-written ffmpeg FFI offsets.

Full history: [CHANGELOG.md](https://github.com/wbs21/CanLapse/blob/main/CHANGELOG.md)

## 中文说明

**v1.3.1 更新内容 — 全项目代码审查 + 性能优化批量落地，共 20 项修复。**

- **修复 `Frame::resize_to` 的缩小判断**：旧逻辑用宽高比交叉比较（`nw*sh < sw*nh`），会在"面积变大但形状变化"时误判为缩小（例如 100×50 缩放到 70×80，总面积实际增大了但被错误地送进面积平均路径）。改为真正的面积比较（`nw*nh < sw*sh`）；新增不等比缩放的回归测试。
- **单实例互斥体所有权**：`CreateMutexW` 的 `bInitialOwner` 从 `1` 改为 `0`，让本进程不自持互斥体；`ERROR_ALREADY_EXISTS` 检测不受影响。
- **删除硬编码开发机路径**：`build.rs` 和 `lib.rs` 里不再有 `D:\CapLite\ffmpeg-min` 之类的机器专属路径，依赖发现统一走环境变量 / `tools/*.path` / 仓库内 `deps/ffmpeg-static/`。任何机器 clone 下来就能构建。
- **SessionWriter 队列扩容 4 → 8**：写盘有界通道翻倍，磁盘繁忙时丢帧概率进一步降低。
- **日志改为持久 `BufWriter<File>`**：`log::line()` 不再每次 open+close 文件，进程生命周期内持有 `Mutex<BufWriter<File>>`；4MB 轮转逻辑保留，轮询路径的双重锁合并为一次。
- **帧间差分 u64 块快路径**：`changed_enough_bytes` 在逐像素扫描前，先用 u64 比较跳过连续相同的 8 字节（2 个像素）；时录常见的"画面几乎不变"场景快 4–8×；用 `debug_assert` 守住指针对齐不变量。
- **clippy 零警告**：`cargo clippy --all-targets` 干净通过。
- **新增 4 个集成测试**：`tests/encode_pipeline.rs` 覆盖全链路编码、空目录错误、非法 fps、中途取消产出可播放部分视频。完整测试套件 **52 项通过**。
- **清理死代码**：删除了 `add/`（设计笔记）和 `spikes/`（早期验证原型）。
- **新增 FFmpeg 升级文档**：`docs/FFI-UPGRADE.md` 详细说明手写 FFI 偏移量的三步升级流程。

**运行要求**：Windows 10 / 11 x64，启用 DWM（默认开启）。无需任何运行库——无 DLL、无 .NET、无 VC++ 运行库。
